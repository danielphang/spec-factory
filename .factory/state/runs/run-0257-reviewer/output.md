## Findings

[BLOCKING] reuse: factory/cli.py:849: `_refuse_inside_store` runs `git symbolic-ref -q HEAD` through a raw `subprocess.run`, as do `_head_branch` (`:873`) and `_store_hint` (`:918`), and `_add_store_checkout` (`:888`) and `gitops.last_tracked` (`factory/gitops.py:117`) each run `git rev-parse -q --verify` the same way, beside `gitops.git`, which this repo already has and which the same diff calls three lines later (`:900`, `:904`, `:916`) → three copies of "what is checked out here" and two of "does this ref exist", so a later change to how the harness runs git (an env, a timeout, an error format) misses them. Replace: `_head_branch(repo)` becomes `return gitops.git(repo, "symbolic-ref", "-q", "--short", "HEAD", check=False) or "HEAD"`; A.1.1 becomes `if _head_branch(top) == gitops.STORE_BRANCH:` (symbolic-ref answers on an unborn branch too); `_store_hint`'s `detached` becomes `_head_branch(root) == "HEAD"`; the two `rev-parse -q --verify` checks become `bool(gitops.git(repo, "rev-parse", "-q", "--verify", ref, check=False))` (`-q` keeps stdout empty on a miss). `gitops.common_dir` (`factory/gitops.py:106`) can take the same form. Behaviour is unchanged: `git(check=False)` returns the stripped stdout, which is empty in every case the raw calls test the return code for.

[SHOULD-FIX] factory/gitops.py:126: `remote_branches` matches any remote-tracking ref that *ends with* `/factory-store`, so a remote branch under a namespace, such as `origin/x/factory-store`, counts as a remote carrying the store branch → on a clone with no local `factory-store` and no real remote copy, `init` creates `factory-store` from that unrelated branch and checks its tree out as the store. Probe: in a clone of a repo with branch `x/factory-store` and no `factory-store`, `init --repo-name demo` printed `exit=0 branch=factory-store upstream=origin/x/factory-store same_as_x=yes`: the new store's history is the unrelated branch's, silently. The spec says to count `refs/remotes/*/factory-store` (A.3.2), where `*` is one path segment. Fix: pass the pattern to git, `git(repo, "for-each-ref", "--format=%(refname)", f"refs/remotes/*/{branch}")`, and drop the `endswith` filter.

[SHOULD-FIX] PR description: Known gaps: the coding standard's rule 3 wants Known gaps to list each `factory:` marker the diff adds or to say "factory: markers added: none" (none were added: a grep of the diff finds no new marker), and rule 2 wants the PR description to name the callers of each existing function the diff changes (`init_cmd`'s one caller is the `init` subparser in `build_parser`) → the operator at the gate cannot tell from the description whether a debt marker or a second caller was overlooked. Add the two sentences.

[NIT] factory/cli.py:964: for an existing instance whose store is missing, A.3.1's branch comes from `gitops.integration_branch`, which runs `git rev-parse --abbrev-ref HEAD` when `integration_branch` is null; on an unborn HEAD that raises git's error. Probe: a repo with no commits and a hand-written `.factory/instance.yaml` printed `exit=2` and `git rev-parse --abbrev-ref HEAD: fatal: ambiguous argument 'HEAD'`. The spec says an unborn branch counts as never tracked (A.3.1). Exit is 2 and nothing is written, so it fails safe, and the implementer lists it under Known gaps. Reachable only by hand-placing an instance file in a repo with no commits; the fix, if wanted, is to fall back to `_head_branch(repo)` when `cfg.get("integration_branch")` is empty.
