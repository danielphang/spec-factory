ESCALATIONS:
- A parent whose own parent-close run returned FAILED or SPEC-DEFECT can still close on its sub-ticket's VERIFIED run. Seen in the `ownfail` probe above. Under the new `build.js`, reuse is checked before any parent run starts, so a new build should not reach this state. It can arise for a parent that was parked under the old runtime after a non-VERIFIED parent-close run, then resumed or plain-transitioned after the upgrade. The earlier verdict would then be dropped without notice. The approved spec does not address this case. Decision for the operator: should `_reused_subticket_run` return None when the parent already has a finished non-VERIFIED verifier run? Before the runtime upgrade (Operator step 1), check whether any parked parent is in that state.
- Scenario coverage is a substring match on the sub-ticket's text, so a scenario named only in a negation or an "Out of scope" line counts as covered (`negated` probe). This is the approved design's own rule and its declared limit, not a defect in the build. Whether to tighten it, for example to the plan's coverage map, is a product decision for later.
