# Fix the four role agent templates' YAML frontmatter, test it, and have init report stale target copies (spec-factory #108)

**Where:** the role agent templates in `agents/` (`factory-planner.md`, `factory-spec-critic.md`, `factory-spec-writer.md`, `factory-triage.md`), and the copies `factory init` makes in a target's `.claude/agents/` (`factory/setup.py:180-185`).

**Problem:** four of the six templates have YAML frontmatter that doesn't parse. Each `description:` is a plain scalar that contains `: ` (for example, `Spec factory Spec writer role: investigates the repo …`), and YAML reads that as a second mapping key. Claude Code can't load these agent definitions. The operator saw it reported for `factory-spec-writer.md` (2026-10-13).

**Evidence:**
- `yaml.safe_load` on each file's frontmatter. clerk and stub: ok. planner, spec-critic, spec-writer and triage: `mapping values are not allowed here` (spec-writer: line 2, column 43).
- The templates date from `9b45041` and `f5d8203`. `factory init` copied them into Nanobot on 2026-10-03 (`~/dev/nanobot-upstream`, commit `4d548d574`); those copies are byte-identical to the templates.
- `factory init` copies a template only when the target has no file of that name (`setup.py:182`). So fixing the templates leaves every existing copy broken.
- No run has used them. The Workflow runs here pass `inlineRoles: true`, and `factory drive` runs `claude -p` with the role prompt. That's why nothing failed. Typed role agents (#24, `inlineRoles: false`) would.

**Proposed change:**
- A. Quote the four `description:` values (or rephrase them without `: `), and change nothing else in the files.
- B. A suite test that parses every `agents/*.md` frontmatter with `yaml.safe_load` and checks it has `name`, `description`, `model` and `tools`.
- C. `factory init` reports a target copy that differs from its template (it never overwrites one), so a stale copy is visible. Nanobot's four copies get refreshed by the Driver once A is live.

**Order:** small. Right after T-0048 (#101), before #104.
