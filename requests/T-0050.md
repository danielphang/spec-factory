# The harness owns each role's model: run start refuses a --model the instance doesn't name (spec-factory #107)

**Where:** `factory/workflows/build.js` and `intake.js` (`MODELS = cfg.models`, line 219; agent `model: MODELS[role]`, line 105); `run start --model` (`factory/cli.py:702`).

**Problem:** the Workflow scripts get each role's model from `factory config`, which the haiku clerk relays. The clerk is a model, so it sometimes retypes the JSON instead of copying it. The harness then accepts whatever `--model` comes back. So a role can run on a model the instance never named, and the store records it as if it had.

**Evidence:**
- In spec-factory build `wf_5a1655a5-8f3` (T-0047, 2026-10-12), the clerk relayed `"verifier": "fable"`. `.factory/instance.yaml:42` says `verifier: opus` and hasn't changed since 2026-10-04 (`a69aaf4`). The next build (`wf_f3c2453f-a74`) got `"verifier": "opus"` back from the same file.
- In this store's log, 10 verifier runs started on `fable`: run-0057, 0060, 0193, 0238, 0287, 0334, 0422, 0483, 0486 and 0487. Every other verifier run started on `opus`.
- #2 (closed) told the clerk to relay raw stdout. That doesn't stop a model from retyping it.

**What it means:** those verdicts stand, but they came from a model the operator didn't choose. `factory stats` (#70) counts them under fable, which is correct as a record but not what was configured. Any other value the clerk relays is open to the same mistake. The model is the one we caught.

**Proposed change (harness, no prompt change):**
- A. `run start` takes the role's model from the instance and records it. A `--model` that differs is refused, with both names in the error.
- B. `build.js` and `intake.js` launch the role agent with the model `run start` returned, as `factory/drive.py:186` already does.
- C. A test where `run start` with a wrong `--model` is refused, and where the run records the instance's model.

**Order:** small, and it affects every Workflow run until #89 retires the scripts. Put it next after T-0047 (#100), before the docs round (#101).
